# M6.2 Review Remediation

## Findings addressed

The M6.2 review found that the planner result omitted the caller-supplied
GFLOP-per-token input and its provenance, preventing a complete replay. It
also accepted zero context tokens despite the published schema requiring a
positive context length.

The planner request contract now requires `compute_work.gflop_per_token` and
`compute_work.source`. The CLI requires `--compute-work-source`, preserves both
values in every emitted request, and rejects `--context-tokens 0`.

## Regression evidence

`clr-cli` tests confirm deterministic output includes the compute-work value and
source, and confirm zero context and missing provenance fail parsing. Python
Draft 2020-12 contract tests reject a request without compute work and one with
zero context.

## Scope

This fixes the M6.2 contract review findings only. The M6.2-06 throughput
comparison remains directional and non-promotable as recorded in its benchmark
report; no analytical rate has been retuned.
