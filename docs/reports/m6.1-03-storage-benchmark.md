# M6.1-03 SSD sequential and expert-sized random-read benchmark

## Scope and cache semantics

This records the storage microbenchmark required by M6.1-03. The temporary
payload is 1,056,964,608 bytes: 56 records of 18,874,368 bytes, exactly the
frozen F32 Qwen3-30B-A3B packed-expert payload size. It contains random bytes,
not model weights.

Windows physical filesystem-cache eviction was neither requested nor assumed.
Consequently, the first-touch result means the first read after
FileOptions.WriteThrough and Flush(true), not a cold-device claim. The warm
result follows a complete prior read in the same process and is labelled
likely warm, not guaranteed resident.

## Interpretation

These results are planner inputs only. They do not predict end-to-end tokens/s,
do not establish a controlled physical cold-cache latency, and do not select a
storage backend. Their purpose is to distinguish sustained sequential reads
from expert-sized non-sequential loading so later placement plans can state
their I/O assumptions explicitly.

## Reproduction and validation

    .\scripts\measure_m6_1_03_storage.ps1
    python python\reference\validate_m6_1_03_storage_benchmark.py --input docs\benchmarks\m6.1-03-storage-benchmark-v1.json

The script preflights free space, uses one unique flat run directory, and
removes only that generated directory in a finally block. The validator rejects
missing distributions, invalid percentile ordering, a cold-device claim, or a
retained run directory.
