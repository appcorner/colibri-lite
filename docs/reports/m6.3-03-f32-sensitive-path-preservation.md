# M6.3-03 F32-Sensitive Path Preservation

## Result

The Layer-0 group-128 candidate now has a routed-expert adapter that receives
the existing `RouterOutput` by immutable reference. It combines direct INT8
expert outputs using the F32 router's selected IDs and routing weights; it does
not recompute, quantize, mutate, or replace router state.

The adapter's inputs are the F32 post-attention-normalized hidden state and the
F32 router output. It is intentionally confined to MoE expert evaluation. The
following remain on the existing executable `reference-f32-v1` path:

- input/post-attention RMSNorm;
- attention, Q/K normalization, RoPE, residual addition, and KV cache;
- router logits, deterministic top-k selection, and routing weights;
- dense tensors, softmax, final normalization, and LM head.

## Regression evidence

The routed-candidate test builds a valid one-layer, two-expert, group-128
configuration. It supplies a selected-expert ID and routing weight through an
F32 `RouterOutput`, then verifies all of the following:

1. selected IDs, router logits, and routing weights are unchanged after the
   candidate call;
2. the candidate's routed MoE output exactly equals the existing F32
   `routed_experts` output when that test's INT8/scales are independently
   reconstructed for the F32 oracle; and
3. the direct-consumption tests from M6.3-02 continue to reject invalid input
   and report zero F32 weight materialization.

This is a synthetic kernel-integration regression, not an oracle comparison of
the full Qwen3-30B-A3B artifact. M6.3-04 must provide the frozen bilingual
fixture, router-ID, checkpoint, logit, and quality comparison evidence.

## Scope and limits

No router, norm, dense, cache, or public cross-crate contract changed. No model
artifact was generated and no tolerance was changed. The candidate remains a
private Layer-0 experimental adapter; it is not used by default generation and
does not make a performance or quality claim.
