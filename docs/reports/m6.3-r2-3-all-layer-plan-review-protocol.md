# M6.3-R2.3 All-Layer Plan Review Protocol

## Goal

Design a bounded, reviewable path from the validated D5 three-sentinel policy to a future 48-layer candidate without extrapolating precision or speedup from unmeasured layers.

Contract: `models/qwen3-30b-a3b/m6.3-r2-3-all-layer-plan-review-contract-v1.json`

Contract SHA-256: `4c4f37356e01d57b247664d0c2537b2f928ad329863778f98a9de0b54624ba2c`.

## Frozen starting map

- Layer 0: admitted existing policy, group32 gate/up/down with native AVX2+FMA and scalar fallback.
- Layer 24: admitted existing policy, F32 gate/up plus scalar group8 down.
- Layer 47: canonical F32 required by existing evidence.
- Layers 1-23 and 25-46: `unmeasured_default_f32`. No neighboring-layer interpolation is allowed.

## Future per-layer characterization ladder

For every unmeasured layer, the future implementation contract must apply the same deterministic decision grammar. It may not skip directly to a precision policy because a nearby layer passed.

1. Start from canonical F32 and establish same-input router/output controls.
2. Test complete group32 gate+up+down as a diagnostic, not as an assumed default.
3. If complete group32 fails the frozen local error limit, run the full seven projection-subset grammar used by D3: gate+up+down, gate+up, gate+down, up+down, gate, up, down.
4. For any projection subset eligible for precision refinement, evaluate group32, group16, and group8 independently. Do not assume smaller groups reduce error; D2 showed non-monotonic behavior.
5. Select the coarsest/lowest-byte candidate that passes the frozen local quality limit; otherwise keep the projection or whole layer F32.
6. Run sequence-aware prompt-plus-frozen-generated-token validation before a layer can enter the cumulative candidate set.

The existing `<=0.001` candidate-to-F32 routed-output limit remains the maximum local error budget unless a future contract strengthens it before candidate execution.

## Cumulative interaction admission

Independent layer PASS is not sufficient because R2.2 showed cross-layer interactions. Future admitted layers therefore enter a cumulative candidate deterministically:

- Rank eligible non-F32 layer candidates by increasing worst sequence-aware local error divided by logical bytes saved; tie-break by lower layer ID.
- Add candidates in fixed batches of four layers.
- After every batch, rerun the frozen full-model bilingual quality guard.
- If a batch fails, bisect that four-layer batch by ascending layer ID; test the lower half then upper half against the last accepted cumulative state.
- Any single layer that fails cumulative admission reverts to F32 and is locked out for that contract. No threshold changes or alternate precision retries are allowed after cumulative failure.

## Full-model quality re-entry

Before performance timing, the final cumulative all-layer candidate must pass at least the accepted D5b semantic gates: exact frozen generation, prompt argmax/top-20, finite logits, deterministic repeatability, router guards, local candidate/F32 budgets, and the existing compact-logit envelope. A future implementation contract may strengthen the held-out workload before execution but may not weaken these gates.

## Production artifact/layout plan

The future runtime may consume only the exact admitted projection representations. It must not reconstruct complete F32 projections or whole F32 experts on a candidate path solely for convenience. Each layer artifact must have a frozen byte layout, SHA-256 identity, direct reader, explicit scalar/native backend boundary, and F32 fallback.

## Performance/resource proof

Official all-layer performance timing is blocked until final cumulative quality passes. The future performance contract must be pre-registered before any official timing and must use fresh paired processes, balanced path order, bilingual workloads, process memory peaks, wall/prefill/decode throughput, and logical expert/candidate bytes. Physical SSD-byte claims require a separately revalidated Windows telemetry method; first-process-touch and likely-warm labels must not be relabeled as controlled cold/warm device I/O.

## Impact model

The review may use measured D5 end-to-end results and exact layer/artifact byte accounting. It must report lower, central, and upper projections as models only, state interaction and depth-sensitivity uncertainty, and must not multiply sentinel speedup by 48 or present a modeled number as measured all-layer performance.

## Review decision

A review `GO` requires every one of the 48 layers to have an explicit status and future evidence path, deterministic interaction/fallback handling, quality/performance proof plans, and no unauthorized implementation. `GO` authorizes only design of an exact R2.3 implementation contract. `NO-GO` authorizes nothing.
