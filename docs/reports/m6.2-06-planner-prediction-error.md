# M6.2-06 Planner Prediction Error

## Result

The selected CPU/RAM-dense/SSD-expert analytical plan predicts **0.205087
decode tok/s** for the explicit two-token prefill, three-token decode, and
six-token context workload. The recorded M5.3 `long_decode_english` run
observed **0.032605 decode tok/s** for its three decode tokens. The absolute
error is **0.172482 tok/s** and the relative error is **+528.997%**.

The result is deliberately not promotable. The cost model was not retuned.

## Evidence and method

The planner input uses the frozen M6.1 doctor/model profiles and their hashes.
The 5.460983808 GFLOP/token input is the sum of `estimated_flops` in each
recorded `decode_*` phase of the M5.3 detailed profile. The observed value and
its runtime/profile hashes are recorded in
`docs/benchmarks/m6.2-06-planner-comparison-v1.json`.

The error formula is `(predicted - observed) / observed`; it is not an
absolute-percent value and is not used to alter any rate or workload term.

## Comparability limit

This is a directional historical comparison only. The M5.3 run predates the
M6.1 hardware profile, uses an 8 GiB expert cache rather than the M6.2 SSD
candidate's zero resident expert-cache bytes, and includes reader/hash behavior
outside the M6.1 storage microbenchmark. It also lacks the M6.1 profile hashes
and repeated cold/warm distribution required for a promotion decision.

M6.2 therefore closes with an explicit measured error, but no approved
throughput recommendation. A future benchmark must use the exact M6 plan,
profile hashes, cache policy, fixture, and repeated cold/warm protocol before
promotion.
