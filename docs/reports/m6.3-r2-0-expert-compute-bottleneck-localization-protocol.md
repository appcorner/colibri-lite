# M6.3-R2.0 Expert Compute Bottleneck Localization Protocol

## Purpose

R1.3 proved that the admitted group-32 Layer-0 representation reduces logical expert bytes but does not turn that reduction into repeatable runtime benefit. R2.0 is designed to identify where the current direct packed path loses time before any new optimization is proposed.

R2.0 is not a speedup benchmark and is not a candidate-admission gate. Its only product is a measured bottleneck classification and an evidence-backed R2.1 hypothesis.

## Reference-only fixture freeze

Before the first candidate timing sample, run the unchanged F32 Layer-0 path for `short_english` and `short_thai` and persist a versioned fixture record containing:

- token IDs;
- exact Layer-0 expert input tensor dimensions and F32 byte SHA-256;
- exact selected expert IDs in token/rank order;
- exact router weights and F32 byte SHA-256;
- unique selected expert IDs;
- reference routed-expert output SHA-256.

Candidate timing is prohibited until this reference-only record and its hash are frozen. The later execution manifest must bind the fixture-record hash, instrumented source commit, release binary SHA-256, timer implementation, and collector/version identities.

## Process matrix

For each of the two fixtures and each measurement view, run five fresh process pairs. The pair order is fixed as `candidate/reference`, `reference/candidate`, `candidate/reference`, `reference/candidate`, `candidate/reference`.

This gives 2 fixtures x 2 views x 5 pairs x 2 paths = 40 process samples. No failed sample is automatically retried. An invalid sample stops that fixture/view condition and requires an append-only review before replacement.

## Timed iteration rules

Each process performs two untimed warm-up iterations. `load_plus_compute` then performs ten timed iterations. `compute_only_preloaded` performs twenty-five timed iterations after all required expert payloads are loaded and decoded outside the timed boundary.

Per iteration, output consumption and hashing occur after the measured expert scopes so the compiler cannot discard results and digest cost cannot contaminate stage timing.

`load_plus_compute` resets only software expert state before each timed iteration. It does not flush the Windows filesystem cache and does not claim disk attribution. R1.3 remains the source of truth for process-correlated physical-I/O evidence.

## Stage families

| Family | F32 reference | group-32 candidate |
| --- | --- | --- |
| `load_decode` | ExpertStore lookup/load + F32 payload decode | seek + packed value/scale reads + decode/validation |
| `gate_projection` | F32 gate matvec | packed gate fused dequant+dot |
| `up_projection` | F32 up matvec | packed up fused dequant+dot |
| `activation_product` | SiLU(gate) x up | same arithmetic |
| `down_projection` | F32 down matvec | packed down fused dequant+dot |
| `routing_accumulation` | occurrence scan + weighted output accumulation | same orchestration |
| `exclusive_residual` | measured parent time not assigned to children | same |

Raw subscopes are retained in evidence; the families above are used only for cross-path classification.

## Required evidence per process

Record fixture, view, path, pair/order, process identity, release binary SHA-256, frozen fixture SHA-256, timer calibration, timed iteration count, expert occurrences, unique expert loads, parent expert total nanos, every raw child-scope total/exclusive/min/max/calls, logical expert bytes, output SHA-256, and instrumented/uninstrumented control total.

Report stage time both as absolute nanoseconds and normalized per expert occurrence. For `load_decode`, also report per unique expert load. Report each process pair, median, minimum, maximum, and directional count; do not retain only aggregate means.

## Instrumentation validity

A no-op timer calibration runs in the same release binary. A child stage whose median duration is less than 20x the median no-op scope cost is not interpreted independently and is merged into the parent classification family without subtracting timer overhead.

For both fixtures and both paths, five paired instrumented/uninstrumented `compute_only_preloaded` controls must show median instrumentation overhead <=5% and every pair <=10%. Instrumented and uninstrumented output SHA-256 must match exactly. A failure invalidates localization rather than allowing a post-hoc correction.

`compute_only_preloaded` is invalid if timed payload-read counters increase. `load_plus_compute` is invalid if software cache reset or expected logical-byte accounting cannot be proven. Parent/child timer nesting must reconcile and exclusive residual must be explicit.

## Classification and R2.1 mapping

Apply ADR 0079's prospective rules exactly. `packed_projection_compute_bound` maps to an R2.1 design study for optimized/fused expert compute such as a native dequant+GEMM backend. `load_decode_bound` maps to read/parse/buffer/placement work. `routing_accumulation_bound` maps to dispatch/combine work. `mixed_or_distributed` requires a narrower follow-up diagnostic before implementation.

R2.0 cannot authorize any of those implementations by itself. M6.4 remains blocked.
