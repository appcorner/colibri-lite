# M6.3-02 Direct Group-128 Expert Consumption

## Result

Implemented the private M6.3 Layer-0 candidate module in
`clr-qwen3-moe::quantized_layer0`. It accepts only row-major INT8 values and
F32 input-group-128 scales, then applies each scale inside the scalar F32
accumulation loop. The candidate does not accept an F32 weight projection and
does not construct one during evaluation.

The module is intentionally not connected to the router or full runtime yet.
M6.3-03 owns that integration while preserving the independently executable
F32 path and all F32-sensitive operations.

## Direct-consumption contract

- scope: one Layer-0 routed expert representation;
- group size: exactly 128 input columns;
- quantized values: signed INT8 `[-127, 127]`; `-128` is rejected;
- scales: one finite, non-negative F32 value per output-row/group;
- arithmetic: `input[column] * (INT8[column] * scale[group])`, accumulated in
  deterministic scalar F32 order;
- outputs: F32 gate, up, activated-product, and down checkpoints;
- forbidden: F32 projection/expert materialization, SIMD, FFI, threading,
  mmap, prefetch, GPU, and custom allocator.

The direct-consumption metric records every quantized value read and records
`f32_weight_values_materialized = 0`. Activation/output vectors are necessary
F32 intermediates, not reconstructed weight storage.

## Tests

The new Rust tests verify:

1. direct group-128 projection equals a separately reconstructed F32 oracle;
2. the Layer-0 expert consumes all three quantized projections directly,
   produces checkpoint shapes, and materializes zero F32 weight values; and
3. invalid group layout, `-128`, non-finite scales, and non-finite inputs fail
   before evaluation.

The synthetic direct-consumption case reads 49,152 INT8 values across gate,
up, and down and reports zero materialized F32 weight values. It is a contract
test, not a model-quality or throughput measurement.

## Provenance and limits

No model-derived group-128 artifact is generated in this task; consequently no
large artifact or conversion run is created. Before a real artifact is made,
it must meet ADR 0057's source revision, F32 manifest, command/tool-version,
hash, layout, and temp-artifact-policy requirements.

The M4.3 group-128 evidence remains directional. This task neither changes the
frozen F32 tolerance registry nor claims Thai/English quality, router agreement,
logit agreement, RAM use, physical I/O, or tokens/s.
