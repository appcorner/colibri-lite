# M6.3-R2.2-D5c Measurement Transport Failure

The first D5c official execution attempt stopped on its first process before any sample was admitted. The inference test itself exited successfully, the READY/GO boundary completed, and 1,165 process-memory observations were collected. The reused R1.3 ETW parser returned `not_measured`, causing the collector to exit non-zero as designed; no automatic retry occurred.

The trace contains 3,593 logical artifact File Read events but zero exact Kernel File/Kernel Disk correlations. Removing the disk-PID filter still yields zero correlations. Exact intersections across FileKey, FileObject, IRP, Disk FileObject, and IORequestPacket are all empty on the current Windows ETW rendering. Heuristic physical-I/O attribution is therefore rejected.

This is not a D5 performance result. The failed sample contributes zero accepted samples and its wall/throughput values are not admitted. Evidence hashes and diagnosis are frozen in `models/qwen3-30b-a3b/m6.3-r2-2-d5c-transport-failure-v1.json`.

ADR 0116 remediates transport by using a D5-specific memory/process collector. D5 does not require physical-read bytes; its frozen metrics are wall time, prefill/decode throughput, working-set/private-byte peaks, logical artifact bytes, expert payload bytes, and candidate artifact bytes. The new collector preserves artifact identity validation, process launch, READY/GO handoff, stdout/stderr capture, and 100 ms process-memory sampling, while removing ETW/tracerpt/parser activity.

A non-official transport smoke passed with process exit 0, READY before GO, active memory sampling, and a metrics file. No smoke performance values are admitted. The next scientific action is a completely fresh 40-process v2 matrix under the unchanged D5 thresholds and pair order.
