## R2.3a - Extended canonical-F32 reference

Before any new candidate layer executes, run canonical F32 only and freeze four generated tokens for both held-out fixtures together with prompt argmax/top-20, selected router guards, fixed/top-20 logit values, and final-norm/prompt-logit hashes. Candidate execution is blocked until this reference has frozen identities.

## R2.3b - Per-layer characterization

Layers `1-23,25-46` are processed independently. Each layer starts from F32 control and evaluates the full `7 x 3 = 21` packed grid: seven projection subsets (`gate+up+down`, `gate+up`, `gate+down`, `up+down`, `gate`, `up`, `down`) at group32/group16/group8.

Every candidate must pass same-input routed-output max-abs `<=0.001` and sequence-aware prompt-plus-first-frozen-generated-token max-abs `<=0.001` across both fixtures. Among passing candidates, select maximum logical bytes saved; tie larger group size, then the frozen projection-subset order. If none pass, the layer remains F32. No depth interpolation or group-size monotonicity assumption is allowed.

Rejected artifacts may be deleted after builder identity, source identity, layout, artifact SHA-256, and evidence are frozen. This avoids retaining roughly model-scale diagnostic storage while preserving reproducibility.

## R2.3c - Cumulative interaction admission

Rank independently selected non-F32 layers by `worst_sequence_local_max_abs / logical_bytes_saved`, tie lower layer ID. Add candidates to the last accepted cumulative policy in batches of four and rerun the four-token bilingual full-model quality gate after each batch.

If a batch fails, split that batch by ascending layer ID and test lower half then upper half against the last accepted cumulative state. Continue until individual layers are isolated. A layer that fails individually falls back to F32 and is locked out for this contract. Do not change thresholds or try another precision after a cumulative failure.

## R2.3d - Production layout and quality re-entry

Freeze the final 48-layer policy manifest and SHA-256 identity for every non-F32 artifact. Candidate paths must directly consume admitted projection representations without reconstructing complete F32 candidate projections or whole F32 experts for convenience. Group32 uses the existing AVX2+FMA backend with scalar fallback; group16/group8 remain scalar packed. No new unsafe boundary is allowed.

Rerun the four-token full-model quality gate through this production layout before any performance timing.

## R2.3e - Paired performance/resource proof

Compare `reference_f32`, `d5_baseline`, and `r2_3_candidate` on both fixtures and both software cache labels. Each cell runs all six three-path permutations exactly once, for `72` fresh process samples total.

GO requires final quality PASS, candidate median wall speedup versus D5 `>=1.0%` in each fixture, candidate wall wins versus D5 `>=5/6` and versus F32 `>=5/6` in every fixture/cache cell, median peak working-set/private-byte regression versus D5 `<=1.0%`, and lower logical expert bytes than D5 in every triplet.

Measure wall, prefill/decode throughput, working set, private bytes, logical artifact/expert/candidate bytes. Do not claim physical SSD behavior from first-process-touch/likely-warm labels.

## R2.3f - Decision review

A final `GO` authorizes only a separate M6.4 entry review. `NO-GO` retains the accepted D5 policy. No result-dependent retry, threshold retuning, triplet reordering, new precision family, native group16/group8, cache-policy change, or historical R2.2c/R2.2d reuse is allowed.
