# M6.1-05 doctor and profile-model

## Result

The CLI now composes the frozen M6.1 evidence into schema-valid hardware and
model profiles. Both commands require explicit input paths, timestamp, runtime
commit, and output path; doctor also requires a Rust version. They do not
download, convert, or copy model weights.

The recorded hardware profile has partial confidence: CPU, RAM, and storage
measurements are present, while all GPU backend and transfer fields remain
unavailable or not run. The recorded model profile describes only the frozen
F32 reference and explicitly does not authorize a quantized format or GPU
backend.

## Outputs

| Command | Output |
| --- | --- |
| doctor | docs/benchmarks/m6.1-05-doctor-v1.json |
| profile-model | docs/benchmarks/m6.1-05-model-profile-v1.json |

The hardware profile carries the M6.1 CPU median of 1.861 GFLOP/s, RAM median
of 65.581 GiB/s, likely-warm sequential storage median of 2.985 GiB/s, and
expert-sized random-read likely-warm median of 3,758.1 MiB/s. Its RAM advisory
budget is 17,768,787,558 bytes and its VRAM budget is zero.

The model profile records the Qwen/Qwen3-30B-A3B pinned revision, 48 layers,
128 experts/layer, top-8 routing, F32 canonical artifacts, 196,608 KV-cache
bytes/token, 7,247,757,312 logical routed-expert bytes/token before cache reuse,
and the frozen bilingual quality hashes.
